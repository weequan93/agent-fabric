## SEC-F04-001 family-budget repair (forward model12)

now installs model12 under the same owned-fixture/migration-lock/digest contract,

by locking billing and ledger relations before inspecting liabilities. A rollback
restores the prior function, original records and ledger exactly; no table drops,
lineage resets or history edits are a recovery mechanism.

The trusted installer captures one immutable parent Run from `parentTaskId`.
Missing, foreign, self and ambiguous parent Tasks refuse. A new child of a Task
with multiple installed Runs requires a future explicit trusted Run-selection
contract; this route is deliberately unqualified. Later Runs cannot retarget an
already captured child. Task/Run allowance subjects are unique within a Space;
a linked Run reuses the existing Task allowance. Child-local ceilings are extra
limits. Admission validates each bound family's own chain and atomically locks
and reserves the set union of all applicable original allowances/accounts in
canonical order. All parent generations up to the bounded ancestry participate;
a union exceeding64 allowance rows refuses without charge.

The original reservation membership is immutable. Unknown usage, original-owner
lookup, once-only settlement, sealed nonacceptance, deficit attribution and cover
use that same frozen list. Parent terminalization or replacement does not erase
liability. Operator inspection includes the inherited ceilings responsible for
budget refusal. The current repository fails closed if model12 lineage is absent.

Disable old admission before an upgrade. An installation with any pre-model12
child reservation refuses migration with `legacy child liabilities require
explicit reconciliation`, including settled history; it does not retrofit old
membership or move counters to make the upgrade pass. Preserve the original
ledger and receipt owner and obtain an explicit remediation decision for that
historical state. Uncharged, unambiguous existing bindings are backfilled inside
the migration transaction. Fresh deterministic owned databases are the qualified
acceptance route; no live deployment or historical external ledger repair is
claimed. E01–E05 and real billing remain pending.

## Qualified installed channels and equivalent retry

The trusted service configuration binds each additional deterministic profile to
an exact local adapter URL and receipt owner ID. `composeNative` snapshots the
full installed channel inventory; qualification probes those same clients.
Duplicate profile IDs, duplicate owner IDs, or ambiguous route/profile-digest
bindings refuse before any adapter I/O. Unavailable channels remain installed
for original accounting recovery, while the registry excludes them from new
admission. Operator commands cannot install destinations or receipt owners.

Cross-profile retry delegates to the installed registry's `selectEquivalent`.
It validates equivalence and the approved pair against the profile selected by
the current choice. Pair ordering cannot override a qualified manual pin or the
current Auto route; an unapproved selected target waits even if another approved
destination is available. Current dispatch rechecks that same exact digest.
The trusted `approvedEquivalentRetries` pairs and the current user's explicit
fallback permission are both required, along with safe evidence from the
original receipt owner and the single native retry budget. The service accepts
no operator-posted policy, URL, owner or receipt. Task details derive an admitted
cross-profile retry's fallback reason from its durable adjacent attempt records;
restarting with no qualification preserves that reason and original-owner
accounting recovery without enabling another dispatch.

second-profile dispatch, explicit switch, denied equivalent policy and permitted
