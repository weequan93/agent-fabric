## Custodian lifetime and safe recovery

The test process owns the custodian by fresh handle, nonce, PID and start/command fingerprint, but the custodian remains alive when that owner or a worker dies. It monitors actual IPC disconnect and an independent monotonic deadline, not a timer in the killed process. Its secure, nonsymlinked, ownership-marked journal lives outside the fixture roots that finally removes. Record fsynced fixture/container/root identities and phase transitions before releasing worker work; capture exact worker/IdP/other child birth+command+nonce+parent identities and ready handshakes before deliberate termination tests. No credentials, DSNs, ephemeral keys or private payloads enter journal exports/raw diagnostics. Full private state stays only in the owned mode0600 ephemeral control files.

Normal worker `finally` and unchanged `stopOwned` run first. After **actual** worker loss, the custodian's separate recovery routine may stop a reparented child only if current PID, birth instance/PGID, full expected Node/script/nonce command, recorded original parent and proof of that parent's death reconcile. It must recheck immediately before signalling and verify absence afterward. Never weaken the original `assertOwned`/`stopOwned` ppid guard, signal a process group, scan/delete by label/prefix alone, or use PID alone. Unknown children or substituted resources cause an inspectable cleanup failure and block qualification. The custodian itself is reaped after its cleanup receipt and every descendant has settled. If the custodian also crashes, its verified journal is recovery input on the next controller invocation; no autonomous cleanup on an unverified historical identity is allowed.

Required interruption fixtures do not spend240s waiting merely to prove the deadline. A separate closed synthetic probe mode uses a short installed deadline with a real worker, real PG/container, real encrypted fsynced file and live IdP, then hangs beyond the deadline. The normal full-predecessor path cannot accept that probe mode or a client deadline. Exercise real worker SIGKILL and real suite-owner disconnect as distinct variants; verify the surviving custodian completes reverse cleanup after each. An injected exception before durable work is not interruption evidence. Receipts record durable phase observed before kill, killed process instance, surviving custodian instance, every child cleanup, root/container absence, original exact before/after censuses and sentinel bytes/liveness. Cleanup failure always returns failure even if a worker passed.
