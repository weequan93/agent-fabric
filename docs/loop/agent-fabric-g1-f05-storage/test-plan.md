## Qualification and test entry points

The supported profile is real local PostgreSQL, current F02 authentication and audience verification, F03/native fencing, F04 native admission and synthetic resource accounting, authenticated encrypted owned files, and `local-extractive-v1` Ask. Extraction consumes persisted eligible values; inference, embedding, reranking and supplier enrichment remain disabled. Restore qualifies loss of content storage with surviving current control/restriction/head authority and separately held fixture keys. Missing or rolled-back current authority must block. This is not whole-cluster disaster recovery.

From the repository root, the single mandatory command to create is `node g1-storage/scripts/check.mjs`. It performs pinned preflight, offline/frozen install, a clean strict build into its own cache, all local suites below, migration compatibility and ownership-checked cleanup, preserving raw failure and success streams. `node g1-storage/scripts/build.mjs` is the independent build command to create. No selective flag may turn the full check green without mandatory cases. Unknown arguments fail. Development may run emitted individual suites using `node --test --test-concurrency=1 --test-reporter=tap g1-storage/node_modules/.cache/storage-build/g1-storage/tests/<suite>.test.js` after the build and owned fixture setup; those results are diagnostic, not controller acceptance.

A denied request must have zero restricted canaries in extractor inputs, outputs, manifests, shared errors and retained diagnostics; zero unauthorized published rows/head changes/bytes. Authorized opaque denial/audit metadata is allowed and explicitly counted. At-rest scans apply even to authorized writes: dump all actual F05 and imported native/model/task/audit/log/event/receipt/outbox/backup retained values and root files; none may contain plaintext payload canaries or fixture key bytes. Decode ordinary encodings/JSON and inspect archive contents; scanning only the new object directory is insufficient. Authorized deliveries and transient controlled test captures are outside at-rest encryption. Assertions compare sensitive values through controlled memory using redacted labels/digests; failed equality diffs and exceptions must not dump plaintext bodies into retained test streams. No production metadata confidentiality or memory-zeroization guarantee is inferred.

Each top-level test name starts with its stable case ID. Parameterized variants get stable suffixes. The runner must prove every catalog ID and required variant executed, not merely see a suite label in stdout. Record positive counts as well as the six finite violation counters: unauthorized disclosure, unauthorized mutation, silent lost update, duplicate canonical effect, restricted-content resurrection, and Ask computer start. Every counter is zero in a qualifying run, and useful save/Ask/forget/restore positives must succeed. A refuse-all implementation fails Q01/R01.

## Required schedules, suite gates and handoff

Mandatory parameter variants are assertions inside the named cases; expand them to separately identifiable executions so a removed variant fails H02/H04. The catalog has 67 local/regression case IDs and 9 pending external IDs. Counts are a minimum coverage registry, not a forecast of Node assertion totals. One table row can have many executed variants. New cases may strengthen coverage; they cannot replace the cases or relax oracles here.

Freeze the race matrix before implementation:

- K06: identical versus changed binding, simultaneous callers and recreated retry; count canonical revision/receipt/event/outbox and installed resource effects.
- K07 and R04: observed original-key lock waits ending in COMMIT, ROLLBACK and timeout, plus actual lost COMMIT acknowledgement. Suppressing an HTTP response alone cannot prove foundation UNKNOWN_COMMIT handling.
- K08 and V02: both possible winners from one expected revision, recreated loser, and independent facts that both succeed.
- Q04/L03: forget, source revocation, membership removal and correction each before disclosure and after an authorized completed disclosure. Full audience is re-resolved, with remaining-member positive.
- L05/L07: delete, expiry, source revoke and correction versus save/promotion/derived publication, with restriction-first and publication-first schedules, late worker restart/duplicate delivery, and session/member expiry after blocked locks. Missing observed schedule is failure.
- R02/R04: restriction during restore wait and before activation, interrupted activation/recreated operator, concurrent original-operation repeat and stale pre-restore writer; no staged data read, no old-head resurrection.
- Shared-source lock ordering: concurrent two-sided share/read/correct/restrict requests in opposite source/destination directions; observe sorted identity/Space/entity lock ordering and bounded refusal/retry on real contention. A deadlock/timeout cannot be caught as successful empty output. A01/A03/L07 must include these variants.
