Keep the two existing installed scanners independent, in harness-copy.ts and
delivery-evidence.mjs. Make their complete reads asynchronous using the pinned

and reads; no shared results, retained file buffers, cached census, coalesced
guard, worker, new driver, dependency, selector, omission or retry. Do not change
Node/libuv environment or the order of original/private guard boundaries.

512KiB buffer per active read unit, incremental SHA256 and actual EOF/byte-count
validation. Open with O_NOFOLLOW, bind the live descriptor to the captured
pathname's native instance before reading, and retain descriptor/path native
coherence after reading. Every successful read consumes every byte; truncation,
growth, descriptor substitution or a native error refuses without a good tree.

call. Measure the actual implemented reader against complete original/private
controls before an H retry; prototype timing cannot qualify a slower or

### PLAN311-01 — invocation-local erased buffer leases

The [Turn311 report](develop-turn311/report.md) identifies allocation churn in
the actual PLAN307 reader:12,928 regular files allocate6,777,995,264 bytes in
fixed512KiB buffers for each complete418,689,614-byte pair. The tester counts
at least635 successful independent pairs in existing H01 controls, before
other preparation/build/final reads. No required guard or recovery is redundant.
An in-memory invocation-local lease prototype returns exact original/private
snapshots in all eight alternating comparisons, with about11%/24% mean savings.
It allocates16 fresh buffers per invocation and clears their contents; no
source change or H retry occurs. Native error, synchronous throw, premature EOF
and an actual-close callback failure refuse after all opened descriptors settle.
These observations support design review, not an actual final-reader or900s pass.

**Fresh independent plan review must precede these buffer changes.** Turn308's
PLAN307 review does not approve this clarification. The nine runtime owners,
all async interfaces and every PLAN307 read/guard remain. Direct changes belong
only in the existing independent HC/D installed scanners and the tester's
existing `register-harness-build-tests.ts` hooks/controls. Other owners change
only for their already prescribed copy/IPC work. No new module, exported pool,
dependency, driver, selector, instrumentation service or preservation layer.

Clarify PLAN307's prohibition on retained file buffers: no plaintext may survive
a read-unit lease, and no buffer may be shared across invocations or scanners.
Fresh per-file hash/count/census results still form the required returned tree;
never cache, coalesce or reuse them across invocations or adopt them as an
expected baseline. Within **one invocation**, use at most16 fresh,
unpooled512KiB backing buffers, initially zeroed, for its at-most16 regular-file
read units. Each admitted unit owns one distinct buffer/backing storage through
all read callbacks, incremental hash updates/digest, descriptor/path validation
and actual descriptor-close settlement. A queued unit owns no buffer or file
descriptor. Lease identity belongs to the logical unit/open generation, never
to a reusable numeric fd. Directory waits still hold no filesystem slot.

Return a lease only in an outer finally after its body and nested close finally
settle. Before return erase every potentially touched byte: track the maximum
written prefix across successful short/full reads; an error, malformed count
or unprovable write range erases the whole512KiB buffer. Erasure failure refuses
the invocation and cannot make a dirty buffer available. Poison buffer admission
on allocation, initial-zeroing or erasure failure: refuse pending/later unstarted
leases before fd/read effects, settle every started IO/close/lease, then reject
with the causes and no partial good tree. Do not strand queued units waiting
for a retired buffer. No buffer is released
at native close syscall completion before its callback, or while hashing or
another native operation can still use it. Every recursive read/close and lease
settles before rejection, recovery, hash advancement or removal. Discard the
invocation's pool after settlement; no parent/private/HC/D reuse, file-result
cache, shared baseline or retained plaintext. This bounds buffer allocation,
not total RSS or latency.

Keep max16 active filesystem operations, every separate successful full read,
512KiB incremental SHA256/EOF/count/O_NOFOLLOW and native eight-field coherence,
all path lists/links/confinement/root/expected-owner equality and root-only
.cache exemption exactly as PLAN307 specifies. Do not change operation order,
Node/libuv environment, concurrency, expected arrays, native failure handling,
existing recovery calls or any product/check/acceptance budget.

distinct simultaneous buffers/backing storage, per-generation lifetime and
zero-before-lease/erased-after-settlement. **PLAN312-01:** for each actual
independent HC/D scanner, run complete original/private many-file scans through
